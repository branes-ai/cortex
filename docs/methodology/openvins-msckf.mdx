A sliding-window filter over IMU poses: the IMU propagates a 15-state nav error and its covariance; each image clones the pose into the window; a feature track that ends is triangulated, its feature marginalized by a null-space projection, and fused into every clone it was seen from; the oldest clone is marginalized to bound the window.

### Contracts

**sensor_model** (S0, Sensor model)

- *Pre:* intrinsics valid; the pixel inside the image
- *Post:* project ∘ unproject is the identity; the analytic Jacobian matches finite differences
- *Test:* `tests/sdk/msckf_stages.cpp` “S0_sensor_model normalizes a pixel…”

**track** (S4, Visual front end)

- *Pre:* consecutive frames; features detected inside the trackable band
- *Post:* tracks inside the image; forward-backward error bounded; ended tracks released in id order
- *Test:* `tests/sdk/msckf_stages.cpp` “S4_frontend ingests observations…”
- *Deviates from the paper:* no RANSAC outlier rejection in the front end; the S6d gate carries it
- *Deviates from the paper:* the shipped default churns (&gt;50% of new tracks lost on their first frame); the border margin is opt-in (#474, #574)

**initialize** (S1a, Initialization)

- *Pre:* an IMU window that is at rest, or frames with enough excitation and parallax
- *Post:* gravity-aligned attitude; the method is recorded
- *Test:* `tests/sdk/imu_init.cpp` “static init recovers gravity…”
- *Test:* `tests/sdk/msckf_dynamic_init.cpp` “the backend bootstraps a moving start via dynamic VI init…”
- *Deviates from the paper:* the dynamic path is excitation-limited on EuRoC and has open SfM defects (#254, #499–#501)

**seed_state** (S1b, Seed the filter)

- *Pre:* a successful seed
- *Post:* P₀ symmetric positive-definite, in the error convention every later node assumes
- *Test:* `tests/sdk/msckf_backend.cpp` “the backend initializes attitude from a stationary window…”
- *Test:* `tests/sdk/tilt_bias_prior.cpp` “S1 prior: P0 is the closed-form tilt-bias block about the seed's up…”
- *Test:* `tests/sdk/tilt_bias_prior.cpp` “S1 prior: P0 covers a static seed's tilt and bias error (NEES 5)…”
- *Test:* `tests/sdk/tilt_bias_prior.cpp` “MSCKF backend: a 0.5 m/s^2 accelerometer bias is learned once the motion rotates…”
- *Decision — the attitude and accelerometer-bias blocks of P₀ on a static seed:* the block the window implies (#609): P_θθ = (σ_ba² + σ_f²)/g²·(I − ûûᵀ) + σ_ψ²ûûᵀ, P_θb = σ_ba²/g·[û]ₓ, P_bb = σ_ba²(I − ûûᵀ) + σ_∥²ûûᵀ (stages::s1_initialization::TiltBiasPrior) over isotropic σ = 0.1 on every core state, uncorrelated (to #609), a tilt σ of σ_ba/g without the correlation. the window measures f̄ = g·u + b_a once, so a seed that takes û from f̄ with b_a = 0 knows the tilt and the horizontal bias only as one sum, δθ⊥ = [û]ₓ(b_a + n̄)/g. The isotropic prior put 99% of that sum in tilt (0.1 rad of tilt is 1 m/s² of gravity, against 0.1 m/s² of bias), so the filter never learned EuRoC's bias and stayed tilted 2.4–2.6° on V1_01. Without the correlation the prior would claim the tilt and bias independent, which the seed is not
- *Decision — σ_ba, the accelerometer-bias prior:* 0.2 m/s² per axis (VioConfig::accel_bias_prior_sigma) over 0.1 (the isotropic value to #609), a datasheet turn-on bias. EuRoC's ground-truth bias reaches 0.55 m/s² (V1_01 y) and is 0.09–0.20 elsewhere; 0.2 puts the largest inside 3σ. The tilt σ that follows is 0.2/g = 1.2°
- *Decision — σ_f, the error of the window's mean specific force:* the larger of the sample scatter over √N and σ_a/√(window) over the white-noise model alone, zero. it bounds how well the window resolves the tilt–bias sum. EuRoC's rotor vibration gives 0.03–0.28 m/s² of per-sample scatter, far above the white-noise model's 0.028
- *Decision — the prior of a gravity-aligned seed (the moving-start fallback):* the fresh state's isotropic σ = 0.1 over the static block with σ_f² adding the window's per-sample scatter and (\|f̄\| − g)², the static block with σ_f² adding (\|f̄\| − g)² only. measured on the gate's five MH_03 draws (four gravity-aligned): a moving window's mean force includes its mean acceleration, \|f̄\| − g = 2.6 m/s² there, so either block gives a 15–16° tilt σ, and the seed's zero velocity (σ 0.1 m/s) is then the wrong part. The first updates explain the velocity by tilt (2.4° → 12–19°), and three draws diverge per backend (3.9–5.2 km at 0.5 px seed 1) against one with the isotropic 5.7°. On the real MH_03 the block gained 0.500 → 0.452 m. The defect is the zero-velocity seed of a moving start
- *Decision — the accelerometer bias along up at a static seed:* seeded from \|f̄\| − g, with σ_∥² = σ_f² + 0.026², half the spread of surface gravity over zero, with σ_ba (to #609). with g known the window measures the bias along up. On EuRoC \|f̄\| − 9.81 is −0.011 to −0.035 m/s² at each sequence's stillest early second against the ground truth's −0.024 to −0.058 along up: it halves that component's error, and the residual is within the gravity σ
- *Decision — the prior of a dynamic (visual-inertial alignment) seed:* the fresh state's isotropic σ = 0.1, the alignment's bias estimate kept in the diagnostics, not seeded over the static block about the alignment's gravity direction, the alignment's bias estimate and its least-squares covariance (#609's scope). measured: the dynamic seed's tilt is accurate (0.14° on the gate's MH_04 draw that diverges, 1.0–1.4° on EuRoC MH_01/MH_02, inside the isotropic 5.7°), and its tilt comes from the alignment, not from the accelerometer mean, so the static correlation does not apply. The alignment's solve is unweighted with a regularized bias, so H⁻¹ is not a covariance. The MH_04 gate divergence is the seeded velocity (0.05 m/s against the truth's 0.42), not the tilt
- *Deviates from the paper:* the S1 bench seeds the mean with the isotropic P₀: its windows carry no duration for the #609 prior, which tests/sdk/tilt_bias_prior.cpp checks

**propagate** (S2, IMU propagation)

- *Pre:* Δt &gt; 0 and bounded; the state initialized
- *Post:* R ∈ SO(3); P symmetric PSD; Φ preserves the 4-D unobservable subspace
- *Test:* `tests/sdk/msckf_stages.cpp` “S2_propagation and S3_augmentation…”
- *Precision:* T2 (msckf/stage_types.hpp) — posit&lt;32,2&gt; passes the bench; P must be written in double on EuRoC (#532)
- *Decision — the IMU input over each interval:* ω and a interpolated linearly between the samples at t_&#123;k−1&#125; and t_k (#616) over the sample that ends the interval, held (#186 to #616), the sample that starts it, held. a sample is the rate at its timestamp: holding either end over the interval integrates the IMU half a sample (2.5 ms) early or late against the camera, NIS 1.1–1.9 on the fast sequences (#616, docs/first-principles/sample-alignment.mdx)
- *Decision — the mean's integrator:* RK4 on the interpolated input: the attitude in closed form (the rate's integral plus the coning term), velocity and position by the RK4 quadrature (geneva2020) over one Euler step on a held sample (#186 to #616), one Euler step on the two samples' average, RK4 on the two samples' average, held. measured against the S2 closure bound (a tenth of 0.5 px over a clone window, tests/tools/gt_spline.cpp) on a 1.3 rad/s flight: an Euler step on the average meets it in rotation but misses position 24×, because it rotates the specific force with the start attitude; RK4 on the average or on the line meets both at second order (0.16 and 0.10 of the position bound). The line is OpenVINS's choice and the closer of the two
- *Decision — an image time between two IMU samples:* the last sample held up to the image time; the rest of the interval integrated from the rate interpolated at the image time once the next sample arrives over hold the frame until the next sample arrives, then interpolate exactly (one IMU sample of latency). no added latency; the residual skew lives only on the partial interval before the image, zero on EuRoC, whose image and IMU stamps coincide (#616)
- *Decision — the transition Φ:* the exact Jacobian of the shipped RK4 mean (#616) over first order, I + A·dt (#186 to #616), I + A·dt at the interval's mean input, a higher-order series of A·dt. a yaw leak is Φ disagreeing with the mean it propagates. #471 found the first-order Φ the least leaky because it sat closest to the one-sample Euler mean; against the RK4 mean it leaks 7× more than before (4.4e-6 per step at 2.5 ms, the S2 sweep). The RK4 mean has the preintegration form, which commutes with a rotation about gravity, so its exact Jacobian preserves the unobservable subspace to roundoff (tests/sdk/imu_interval.cpp, the S2 bench)
- *Decision — the discrete process noise Q_d:* diagonal, σ²·dt per state over G·Q·Gᵀ with the θ–v–p correlations (geneva2020). #212's S2 probe found the full Q_d did not change the over-confidence (docs/pipeline/stages/s2-imu-propagation.mdx)
- *Deviates from the paper:* no first-estimates Jacobians on Φ (FEJ, #606)

**augment** (S3, State augmentation)

- *Pre:* the state propagated to the image time
- *Post:* P grows by 6 with an exact block copy; P PSD
- *Test:* `tests/sdk/msckf_stages.cpp` “S2_propagation and S3_augmentation…”

**triangulate** (S5, Triangulation)

- *Pre:* at least two observations from live clones; enough parallax
- *Post:* positive depth in every camera; bounded reprojection error; conditioning reported
- *Test:* `tests/sdk/msckf_stages.cpp` “S5 and S6a-S6e run one feature track…”

**msckf_update** (S6, MSCKF update)

- *Pre:* the landmark triangulated against the current clones
- *Post:* Nᵀ H_f = 0; P⁺ ⪯ P⁻; no information along the unobservable directions; δx finite
- *Test:* `tests/sdk/msckf_stages.cpp` “S6 composite is bit-identical to CameraUpdater::update…”
- *Test:* `tests/sdk/msckf_camera_update.cpp` “S6d gate line: the chi-square quantile by default…”
- *Test:* `tests/tools/stage_bench_s6.cpp` “S6 update: no information along the unobservable directions…”
- *Precision:* T6, T6e (msckf/stage_types.hpp) — S6e writes P: double on EuRoC (#532); the carried square-root factor holds in posit32
- *Decision — the S6d gate line:* the χ²₁₋α(dof) quantile, α = 0.05 over 5 per dof (before #481). #481: it admits 1 − α of consistent inliers at every dof; the per-dof line admitted most 2σ-biased short tracks
- *Decision — S6c compression:* none (the identity) over QR to n + 1 rows (geneva2020). one feature per update leaves 2m − 3 rows, fewer than the state dimension, so QR would not shrink it
- *Deviates from the paper:* no first-estimates Jacobians on H (FEJ, #606); the yaw leak is S6 moving the mean (95–99%, #480)
- *Deviates from the paper:* S6c compression is the identity (one feature per update leaves 2m − 3 rows)

**marginalize** (S9, Marginalization)

- *Pre:* every track touching the clone has been fused
- *Post:* P is the principal submatrix; P PSD; no observation refers to the dropped clone
- *Test:* `tests/sdk/msckf_stages.cpp` “S9_marginalization keeps the principal submatrix…”

**zero_velocity** (S8, Zero-velocity update)

- *Pre:* both the IMU and the image tests say rest
- *Post:* never fires while moving faster than 0.05 m/s on EuRoC (a measurement, not a guarantee)
- *Test:* `tests/sdk/zero_velocity.cpp` “S8 pseudo-measurements pull v to zero…”

**online_calib** (S10, Online calibration)

- *Pre:* the extrinsic prior σ's stated; enabled before any clone exists
- *Post:* the extrinsic rotation ∈ SO(3); the calibration covariance PSD; estimating moves the extrinsic toward the truth
- *Test:* `tests/sdk/msckf_stages.cpp` “S9_marginalization keeps the principal submatrix; S10 adds calibration states…”
- *Test:* `tests/tools/stage_bench_s9_s10.cpp` “S10: estimating the extrinsic moves it toward the truth…”
- *Deviates from the paper:* extrinsics only (VioConfig::estimate_extrinsics, off by default); no intrinsics; no time offset (#332)

|---|---|---|---|---|

| **NormalizedObs** | data | feature id, camera id, normalized image point (x, y) | `sdk/include/branes/sdk/msckf/stages/s0_sensor_model.hpp` `Result` | ✗ finite, and the ray is in front of the camera (z &gt; 0) |
| **TrackDB** | data | feature id → [(clone time, normalized observation)], plus the tracks that ended this frame | `sdk/include/branes/sdk/msckf/stages/s4_frontend.hpp` `TrackTable` | ✗ every observation's clone time is a live clone, or the observation is purged; ✓ points inside the image; ✓ track length at most the clone window |
| **NavSeed** | data | R, v, p, b_g, b_a, the time, and the prior P₀ in the filter's error convention | `sdk/include/branes/sdk/msckf/stages/s1_initialization.hpp` `seed_from_imu` | ✓ gravity sign and magnitude; ✓ P₀ symmetric positive-definite; ✓ P₀ states what the init window does and does not determine (tilt-bias correlation) |
| **FilterState** | state | nav (θ, p, v, b_g, b_a: 15), clones (θ, p: 6 each), optional camera↔IMU extrinsics (6 per camera), the joint covariance P, and the error-state convention every Jacobian assumes | `sdk/include/branes/sdk/msckf/state.hpp` `State` | ✓ P symmetric; ✓ P positive semidefinite; ✓ R and every clone rotation ∈ SO(3); ✗ the layout and the error convention agree with every node's Jacobians |
| **Landmark** | data | feature position p_f (world), the triangulation's parallax and conditioning | `sdk/include/branes/sdk/msckf/stages/s5_triangulation.hpp` `Result` | ✓ positive depth in every observing camera; ✓ normal-matrix condition number reported |
| **UpdateDiag** | output | NIS, dof, the gate verdict, and where a rejected track stopped | `sdk/include/branes/sdk/msckf/stages/s6_msckf_update.hpp` `Result` | ✓ NIS ~ χ²(dof) over windows (bound χ²₁₋α(dof) per update, α = 0.05, from what **msckf_update** resolves: the S6d gate rejects above it, so a consistent filter loses α of its inliers and no more) |

- **ImageFrame** precision: integer pixels; no arithmetic-type choice
- **NormalizedObs** precision: the narrowest edge that keeps sub-pixel accuracy; float holds (#532)
- **FilterState** precision: stored in double; the P-writing stages must stay double (#532)
- **FilterState** deviates from the paper: error convention R = R̂·Exp(δθ) (body-frame right perturbation); OpenVINS uses a left quaternion error. Legitimate if consistent everywhere.

## Schedule

The driver is `sdk/include/branes/sdk/msckf_backend.hpp`.

```text
on imu (200 Hz):
  initialize  [when not initialized]  — accumulate; static or gravity-align when a window allows
  seed_state  [when a seed is ready]
  online_calib  [when a seed is ready and extrinsics are estimated]  — appends the calibration block; S6 updates it
  propagate  [when initialized]
on image (20 Hz):
  sensor_model
  track
  initialize  [when not initialized]  — try the dynamic VI alignment
  seed_state  [when a seed is ready]  — then return
  propagate  — to the image time
  zero_velocity  [when at rest]  — then return; the frame adds no clone
  msckf_update  for each track touching the oldest clone  [when window full]
  marginalize  [when window full]
  augment
  triangulate  for each ended track (ascending id)
  msckf_update  for each ended track (ascending id)
```
