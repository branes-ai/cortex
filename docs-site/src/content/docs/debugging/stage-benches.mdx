A **stage bench** is the focused debug, test, characterization and research environment for **one**
transformation. It runs the stage on fixtures, in several arithmetic types and implementation
variants, and prints the stage's [invariants](/debugging/invariants/) in native units. A bench is
one small executable, so an edit to a stage costs seconds to re-check, not a EuRoC replay.

## What a bench gives you

- **Debugging:** a failing invariant points at the transformation and names the size of the
  violation.
- **Testing:** fixtures are regression tests, and a captured fixture must replay **bit for bit**.
- **Characterization:** declarative sweeps over noise, Δt, parallax, conditioning or window size,
  written to CSV for the figure pipeline.
- **Research:** alternative implementations of the stage (variants) run on identical fixtures,
  side by side.
- **Mixed precision:** the same stage runs in `double`, `float`, `posit<32,2>`, `posit<16,1>` and
  `long double`,
  each compared with the `double` run.

## Fixtures

| Kind | Input | Judged against | Made by |
|---|---|---|---|
| `known_answer` | synthetic | an analytic expected output, computed independently of the stage | hand, in the bench |
| `ground_truth` | built with truth injected upstream (#266) | the true values the output must reproduce | a synthetic-world run with the mean reset to truth |
| `captured` | a recorded stage boundary | the output the stage produced in that run | `capture(...)`; from real runs via #446 |

The runner adds two checks to every stage's own invariants:

- **`replay.bit_identical`:** a captured fixture, run in the type it was captured in, must reproduce
  its recorded output exactly.
- **`known_answer.residual`:** a known-answer fixture must match within the type's arithmetic
  tolerance.

Fixtures are JSON (`branes.vio.fixture/1`) with an exact codec:

- numbers go through `double`, written in shortest round-trip form;
- non-finite values are written as strings;
- rotations are restored without renormalizing.

A file reads back bit-identical; the tests prove it for −0, denormals, the largest double, ±∞, NaN
and a full captured state.

```json
{"schema": "branes.vio.fixture/1", "stage": "S9_marginalization", "kind": "captured",
 "arithmetic": "double", "source": "synthetic_world, S2/S3/S9 stage sequence, frame 6",
 "input":    {"state": {"R": [...], "p": [...], "clones": [...], "P": {"rows": 39, ...}}, "clone_index": 0},
 "expected": {"state": {...}, "dim_before": 39, "dim_after": 33, "removed_time": ...}}
```

## Running a bench

```bash
cmake --build build --target s9_marginalization_bench
./build/tools/s9_marginalization_bench                         # built-in fixtures; double, float, posit32
./build/tools/s9_marginalization_bench --types double,posit16  # choose number systems
./build/tools/s9_marginalization_bench --variant all           # shipped vs research variants
./build/tools/s9_marginalization_bench --fixture F.json        # e.g. a fixture captured from EuRoC
./build/tools/s9_marginalization_bench --sweep clones=2,4,8 --csv out/
```

The bench prints the stage's contract from the registry, then one report per fixture, variant and
type. This is real output:

```text
  captured_stage_sequence [captured]  variant=shipped  type=double
------------------------------------------------------------------------------
  invariant                               value        threshold    unit            verdict
------------------------------------------------------------------------------
  marginalization.dimension               33           33           count           PASS
  marginalization.principal_submatrix     0            1.386e-13    dimensionless   PASS
  covariance.symmetric                    0            6.541e-13    matrix units    PASS
  covariance.psd                          0            2.829e-12    matrix units    PASS
  window.clones_minus_1                   4            4            count           PASS
  window.removed_the_requested_clone      0            0            s               PASS
  mean.untouched                          0            0            count           PASS
  replay.bit_identical                    0            0            count           PASS
------------------------------------------------------------------------------
  max |output - double output| = 0    stage run time (best of 5) = 7.993 us
```

The same fixture in `float` reports `max |output − double output| ≈ 2e-7`, and every invariant
still passes, because each threshold scaled to `float`'s ε. The bench exits non-zero on any failure,
so it can gate CI. A run that executes nothing, for example an unknown `--types`, also fails rather
than reporting a vacuous pass.

## A characterization sweep

The S9 bench sweeps window size × covariance conditioning and reports, per type, the principal-
submatrix residual, the smallest eigenvalue after removal, and the run time. A sweep makes a
precision limit visible before it bites in a full run:

| clones | log₁₀ κ | λ_min after (double) | λ_min after (posit32) | λ_min after (float) |
|---|---|---|---|---|
| 2 | 0 | 1.0e-2 | 1.0e-2 | 1.0e-2 |
| 2 | 4 | 1.0e-6 | 1.0e-6 | 9.5e-7 |
| 2 | 8 | 1.0e-10 | **−4.1e-9** | **−5.2e-8** |

At κ ≈ 1e8, neither `posit<32,2>` nor `float` can resolve the smallest eigenvalue. The matrix is
still positive-definite in `double`, but not measurably so in the narrower types, and `float` is
an order of magnitude further off than posit32. That is exactly the kind of per-stage precision finding the
[mixed-precision](/debugging/mixed-precision/) work builds on.

## What the first benches found

The S0 and S1 benches (#454) turned up three things on their first run, none of which an end-to-end
metric had shown:

- **The synthetic world's camera isn't quite EuRoC cam0.** Its tangential coefficient p2 is 1000×
  the EuRoC value (1.76e-2 vs 1.76e-5). The ground-truth fixture caught it as a 0.1 disagreement in
  normalized coordinates. The world is self-consistent, so nothing downstream failed.
- **The S1 seeding stage didn't compile for posits:** an implicit `T` → `double` narrowing, now
  explicit.
- **The dynamic visual-inertial alignment is precision-fragile.** It declines entirely in `float` and
  `posit<32,2>` on inputs where it resolves in `double`. Its solve forms normal equations (squaring
  κ), adds a fixed `1e-9` ridge, and needs a Cholesky factorization, which breaks down once κ²
  exceeds 1/ε. That is exactly the kind of per-stage precision finding the
  [mixed-precision work](/debugging/mixed-precision/) is built to act on.

The S2 and S3 benches (#455) added two more:

- **The propagator didn't compile for posits** either: `timestamp += dt` mixed `T` into a `double`
  (now explicit, bit-identical for float and double).
- **Propagation leaks the yaw direction**, as the body-frame filter is known to do. Φ preserves global
  translation exactly, but its first-order form, linearized at the current estimate, leaks yaw by
  ≈2.4e-6 per 5 ms step on a tumbling trajectory. The bench now measures this directly, per step and
  across Δt and dynamics: the propagation half of the observability question behind the
  over-confidence (#212).

The S4 and S5 benches (#456) found four more:

- **Border churn in the front end.** KLT drops features whose window doesn't fit at the coarsest
  pyramid level, a ≈24 px border band at the defaults, but FAST detects up to the edge. On the bench's
  frames about 85% of new detections die on their first tracked frame and are re-detected under new
  ids ([#474](https://github.com/branes-ai/cortex/issues/474)).
- **The forward-backward gate is off by default**, so drifted tracks reach the backend. The bench
  measures them, and its `fb_gate_1px` variant enforces the contract.
- **The camera updater didn't compile for posits:** qualified `std::acos`/`std::sqrt` calls, now ADL.
- **The synthetic world steps from rest to ≈1 m/s** at the end of its warm-up, a velocity jump no
  IMU stream can produce. Pure IMU propagation from rest is off by ≈1 m/s after one frame
  ([#475](https://github.com/branes-ai/cortex/issues/475)).

### The MSCKF update, one sub-step at a time: S6

S6 is five transformations, and each has its own bench, input and contract: the Jacobians (S6a)
against finite differences, the null-space projection (S6b) against NᵀN = I and Nᵀ H_f = 0, the
compression (S6c) against the normal equations, the gate (S6d) against χ², and the update (S6e)
against K·r and P − K S Kᵀ. Each sub-step's fixtures come from running the ones before it, so a
failure points at one sub-step. The S6 benches (#457) found:

- **The update isn't the leak.** At the estimated state as much as at the true one, the projected
  Jacobian annihilates the unobservable directions (global position, yaw) to ≈1e-16, and the update
  adds no information along them. The over-confidence of #212 has to come from linearization points
  drifting apart across stages, not from S6.
- **The shipped χ² gate is loose at low dof.** Inliers are χ²-consistent, but with 1–3 dof the
  5-per-dof gate admits 59–70% of measurements biased by 2σ, against 22–44% for a 95% χ² gate.
- **The square-root update is the less precise one in posits:** ≈330× further from its double
  result than the Joseph form in posit32.
- **Posits are precise near 1, not near 1e-17.** Residuals at the true state and covariance entries
  near σ² sit where a posit has few fraction bits, so checks on them use T's precision at that
  magnitude (`safety_at`), not its ε at 1.

### Comparing alternative methods: S5 triangulation

A bench variant can run a different algorithm, not just different parameters. The S5 bench runs
three alternatives to the shipped ray-perpendicular solve with Gauss-Newton refinement: the two-view
midpoint, the DLT, and anchored inverse depth with Gauss-Newton. All four pass every fixture in every
type, and the sweep shows where they differ (mean depth error in m, feature at 5 m):

| parallax | px noise | shipped | midpoint | DLT | inverse depth |
|---|---|---|---|---|---|
| 0.25° | 0.5 | 2.38 | fails | 1.60 | 2.41 |
| 5° | 1 | 0.140 | 0.168 | 0.147 | 0.140 |
| 15° | 1 | 0.0455 | 0.0553 | 0.0465 | 0.0455 |

- **Inverse depth gives the shipped answer.** Both minimize the reprojection error, so the
  parameterization changes the path, not the answer.
- **The DLT is biased toward the cameras.** It wins where depth is barely observable and costs ≈5%
  where it is observable.
- **The midpoint is the worst.** It is also the only one that loses precision with exact
  observations: its closed form cancels catastrophically at low parallax in float.
- No method recovers a depth the geometry doesn't hold. Below about 1° the parallax gate is the
  answer, not the solver.

The S4 inspector, which draws the front end's tracks on EuRoC frames, now calls the extracted stage
too. What it shows is what the estimator does.

## Writing a bench

A bench is a struct describing its stage: the I/O types, the codec, `run` (which calls
`stages::<sN_name>::apply`, with research variants as extra branches), `flatten` (every output
number, for the cross-type and replay comparisons), `invariants` (the stage's checks), the built-in
fixtures, and optionally a sweep. `bench_main<B>` turns it into the executable. The S9 bench
(`tools/include/branes/tools/bench/s9_marginalization_bench.hpp`) is the template; the developer
reference spells out the full contract.

## The edit-compile-run loop

Measured by touching the stage header, then rebuilding and running only the bench target
(i7-12700K, gcc 13.3, `-j4`):

| Build | Rebuild | Run: double, float | Run: + posit32 |
|---|---|---|---|
| default (no `-O`) | 4.3 s | 0.08 s | 9.1 s |
| Release (`-O3`) | 8.4 s | < 0.01 s | 1.1 s |

Posits are software arithmetic, so posit work is best done in a Release build. Either way, a stage
edit is re-checked in seconds.
